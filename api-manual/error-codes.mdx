# Error Codes

This page describes common response formats for generation and native Chat Series endpoints. Use the HTTP status and the endpoint-specific error body.

## Response Format

### Success Response

Generation submission returns a response with `code: 200`. Native Chat Series responses use their protocol-specific format:

```json
{
  "code": 200,
  "data": {
    "task_id": "task-unified-1757165031-uyujaw3d",
    "status": "running",
    "created_time": "2025-11-12T10:30:00"
  }
}
```

### Error Response

Generation endpoints return the HTTP error status with a detail field. They do not wrap errors in code and error:

```json
{
  "detail": "task_id is required"
}
```

### Native Chat Series Errors

Chat Completions and Responses use an error object; Claude Messages adds type=error; Gemini uses error.code, error.message, and error.status. Authentication failures may still use detail. Upstream error status codes and bodies are forwarded unchanged. Successful JSON responses and SSE events are not wrapped in code and data.

### Task Failed Response

When a task fails during processing, the response includes `status: "failed"` with an error message:

```json
{
  "code": 200,
  "data": {
    "task_id": "8FDN1I7M7Q68DDG8",
    "status": "failed",
    "files": [],
    "created_time": "2025-11-25T08:50:13",
    "error_message": "The prompt violates our content policy"
  }
}
```

## HTTP Status Codes

### 200 - Success

Request completed successfully. For generation endpoints, check `data.status` to determine task state. Native Chat Series returns its JSON response or SSE stream directly.

### 400 - Bad Request

The request contains invalid parameters or data.

**Example:**

```json
{
  "detail": "task_id is required"
}
```

### 401 - Unauthorized

Missing or invalid credentials. Authentication errors use a detail field.

### 402 - Payment Required

Native Chat Series endpoints use HTTP 402 for insufficient credits. Generation submission uses HTTP 400 for insufficient credits.

**Example:**

```json
{
  "error": {"message": "Insufficient credits", "type": "invalid_request_error", "code": null}
}
```

### 403 - Forbidden

Access denied due to permission restrictions.

**Example:**

```json
{
  "detail": "You do not have permission to access this resource"
}
```

### 404 - Not Found

The requested resource does not exist.

**Example:**

```json
{
  "detail": "Task not found"
}
```

### 408 - Request Timeout

The request timed out before a response was returned. The timeout middleware returns plain text:

**Example:**

```text
Request timeout
```

### 422 - Unprocessable Entity

Malformed JSON or a request body that is not an object may be rejected before endpoint handling. The detail field is an array of validation errors.

### 429 - Too Many Requests

Rate limit exceeded.

**Example:**

```json
{
  "detail": "Rate limit exceeded. Please try again later."
}
```

### 500 - Internal Server Error

An unexpected server error occurred.

**Example:**

```json
{
  "detail": "An internal error occurred. Please try again later."
}
```

### 502 - Bad Gateway

Upstream service error.

**Example:**

```json
{
  "detail": "Upstream service unavailable"
}
```

### 503 - Service Unavailable

The model capability or billing configuration is not approved. An unknown or disabled public model normally returns HTTP 404.

**Example:**

```json
{
  "detail": "Model billing configuration is not approved"
}
```

## Error Handling Best Practices

<Tip>
**Retry transient failures carefully**: For temporary 500 or 502 errors, use exponential backoff. Retrying submission can create another task. An unapproved model configuration reported as 503 requires a configuration update before retrying.
</Tip>

<Tip>
**Handle rate limits**: When receiving 429 errors, wait before retrying. Consider implementing request queuing.
</Tip>

<Tip>
**Validate inputs**: Check your request parameters before sending to avoid 400 errors.
</Tip>

<Tip>
**Monitor credits**: Generation submission reports insufficient credits as HTTP 400; native Chat Series reports HTTP 402.
</Tip>
