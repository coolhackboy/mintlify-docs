GPT Image 2.6 Sunburst Text to Image generates one image from a text prompt, from quick product shots to transparent assets and exact-pixel layouts at 1K, 2K or 4K. Sunburst is the GPT Image 2.6 option for detailed visual work and precision-focused editing.

For reference-image editing, use [GPT Image 2.6 Sunburst Image Edit](/api-manual/image-series/gpt-image-2-6-sunburst-edit) (`openai/gpt-image-2.6-sunburst/edit`). GPT Image 2.6 accepts the same parameters as [GPT Image 2.5 Sunburst](/api-manual/image-series/gpt-image-2-5-sunburst-text-to-image), plus `output_compression`, `moderation` and `complexity`.

## Models

- **openai/gpt-image-2.6-sunburst/text-to-image** — Text to image with GPT Image 2.6 Sunburst, one image per request.

## Features

- Text-to-image from a prompt of up to 32,000 characters.
- Three resolution tiers (`1K`, `2K`, `4K`) with aspect-ratio presets, `auto`, or custom `WIDTHxHEIGHT` sizes.
- Five quality tiers: `low`, `medium`, `high`, `xhigh`, `max`.
- Transparent or opaque backgrounds; PNG, JPEG or WebP output.
- Adjustable JPEG/WebP compression, moderation strictness and planning effort (`complexity`).

## Required parameters

- `prompt` (string): Text describing the desired image. Up to 32,000 characters; must not be blank.

## Optional parameters

- `size` (string): Aspect-ratio preset, `auto`, or custom `WIDTHxHEIGHT`. Default `1:1`. See [Size](#size).
- `resolution` (string): `1K`, `2K` or `4K`. Default `1K`.
- `quality` (string): `low`, `medium`, `high`, `xhigh` or `max`. Default `high`.
- `background` (string): `auto`, `transparent` or `opaque`. Default `auto`. A transparent background requires `png` or `webp` output.
- `output_format` (string): `png`, `jpeg` or `webp`. Default `png`.
- `output_compression` (integer): Compression level from `0` to `100`. Only allowed when `output_format` is `jpeg` or `webp`. When omitted, the default compression applies.
- `moderation` (string): Content moderation strictness, `auto` or `low`. Default `auto`; `low` applies less restrictive filtering.
- `complexity` (string): Planning effort the model spends before generating, `low`, `medium` or `high`. Default `high`. Does not change the price.

## Size

- Presets: `1:1`, `2:3`, `3:2`, `4:3`, `3:4`, `4:5`, `5:4`, `16:9`, `9:16`, `21:9`. When `size` is omitted, the output is `1:1` at the selected `resolution`.
- Presets keep the selected `resolution` tier; actual pixel dimensions may vary between generations. Use a custom size when you need exact pixels.
- `auto` lets the model choose the size (about 1.5 megapixels). It works with any `resolution` and is billed at the `1K` tier.
- Custom `WIDTHxHEIGHT` (use `x` or `X`, for example `2304x1536`) works with any `resolution`. Both edges must be multiples of 16, the longest edge must not exceed 3,840 pixels, the aspect ratio must not exceed 3:1, and total pixels must be between 655,360 and 8,294,400.
- A custom size is billed at the tier that matches its total pixels, or at the selected `resolution` if that is higher:

| Total pixels (custom size) | Billing tier |
| --- | --- |
| Up to 1,572,864 | `1K` |
| 1,572,865–4,194,304 | `2K` |
| Above 4,194,304 | `4K` |

## Examples

- **Generate one image**: a studio product photo, `1:1`, `1K`, with a `callback_url`.
- **Transparent asset**: a cutout with `background: transparent`, WebP, `4K`, `xhigh` quality.
- **Custom size**: a panoramic scene at `2304x1536`, `2K`, `medium` quality.
- **Compressed JPEG**: `3:2`, `medium` quality, `output_format: jpeg`, `output_compression: 80`.

## Notes

- Each request returns exactly one image; `n` other than `1` returns 400. Fields not listed above return 400. `model` and `callback_url` belong at the request root, not inside `input`.
- A transparent background with `output_format: jpeg` returns 400. `output_compression` with `output_format: png` also returns 400.
- Credits depend on `quality` and the billing tier (`resolution`, or the custom-size tier described in [Size](#size)). `complexity` and `moderation` do not change the price. The per-image maximum is reserved at submission; when the task finishes you are charged for actual token usage, up to that maximum, and the rest is refunded. A failed task is refunded in full.
